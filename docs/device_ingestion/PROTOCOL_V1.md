## Протокол

`POST /v1/telemetry`, `Content-Type: application/json`,
`Authorization: Bearer <device-token>`.

Обязательные поля: `schema_version=1`, UUID `device_id`, `message_id`, `stream_id`,
положительный bigint `sequence_no`, `captured_at` (RFC3339 с зоной либо null),
`payload` (непустая карта имён датчиков и конечных числовых показаний).
Boolean не является показанием. Неизвестные поля, повторные JSON-ключи,
NaN/Infinity и несинхронизированное время без зоны отклоняются.
Лабораторные защитные ограничения: 64 KiB на запрос, 128 датчиков,
64 ASCII-символа на имя датчика. Это ограничения данного пилота, не всех TLM-систем.
Единицы и реальные имена задаёт интеграция конкретного оборудования.
`received_at` определяет только БД при первой вставке.

Устройство собирает пакет каждые 10 секунд и сохраняет его до отправки.
Повтор сохраняет все исходные поля, включая message_id и captured_at.
Новый запуск создаёт новый stream_id; старая очередь сохраняет старые сообщения.

Новая строка: 201/stored после COMMIT. Идентичный повтор: 200/duplicate.
Одинаковый ID с другим содержимым или повторное использование stream position:
409. Неверный credential: 401; несовпадающий device_id: 403.
5xx/timeout/429 не означают доставку: сообщение остаётся в очереди.
Политика отзыва token действует при аутентификации каждого запроса;
уже аутентифицированный запрос может завершиться одновременно с отзывом.

## Хранение и безопасность

Новая ordered migration создаёт `tlm.devices`, `tlm.device_credentials`,
`tlm.telemetry_messages` и NOLOGIN-группу `tlm_ingest`.
Отдельный runtime LOGIN создаётся оператором, а не миграцией с паролем в Git.
Он получает группу tlm_ingest, SELECT и ограниченный INSERT, но не UPDATE/DELETE.
Группа не обходит RLS. Схему tlm не добавлять в Data API exposed schemas.
Token устройства генерируется из 32 случайных байтов; в БД хранится SHA-256.
Device token и database credential различны. API не доверяет device_id из JSON.

Уникальность `(device_id, message_id)` обеспечивает идемпотентность;
`(device_id, stream_id, sequence_no)` запрещает повтор позиции потока.
payload хранится в JSONB, одно сообщение — одна строка.
received_at — время вставки на часах БД, не время измерения или COMMIT.
История append-only; current_state отсутствует намеренно.
Права доверенного backend НЕ реализуют изоляцию школ/учеников.
Существующие ingest_messages, fixture contract и их тесты не изменяются.

## Последовательность

1. Контракт, новая миграция и проверки схемы.
2. Настоящий API, PostgreSQL adapter, restricted-login HTTP → PostgreSQL tests.
3. Linux/Python агент с постоянной очередью, явным sensor adapter,
   provisioning-инструменты и инструкция развёртывания стенда.

Обязательный CI использует только локальный disposable Supabase и software input.
Удалённая dev-БД, API-хост и реальные датчики не считаются подключёнными только
потому, что код написан. Конкретные credentials, endpoint и sensor driver пока
не предоставлены. Их нельзя подменять случайными данными или production secrets.
